# ADR：可选的项目内执行模型（双模型决策执行器）

- 状态：已接受（代码已编写，未验收）
- 日期：2026-10-30
- 相关：`docs/DECISION_EXECUTOR.md`、`docs/DECISION_EXECUTOR_ACCEPTANCE.md`

## 背景

项目原有架构约定是：**不由项目调用模型，也不保存模型密钥**。外部宿主（DSH、Codex、Claude Code 等）负责模型循环，Bridge 只提供工具、观察与控制。

用户新需求是：主模型把目标派给项目内的执行模型，由项目持续观察、决策、操作，以提高自主游玩效率。若只增加“任务表 + 记忆面板 + 提示词”，并不满足该需求。

同时，强制所有人配置模型服务会破坏现有用户的直接玩法，也会让项目承担不必要的凭据风险。

## 决策

1. **执行模型是可选扩展，默认关闭。**
   关闭时不调用执行模型、不读取密钥内容、不创建任务记录；原有直接 MCP 模式保持不变。

2. **只有在启用后才加载独立配置与凭据。**
   配置在 `<dataRoot>/decision/config.json`，密钥在 `<dataRoot>/decision/secrets.json`，任务库在 `<dataRoot>/decision/decision.sqlite`。
   模型密钥不进入可导出的 `config.json`，不回传页面，不进入日志、SSE 与问题包。

3. **旧约定的适用范围收窄，而不是被删除。**
   “项目不调用模型/不保存模型密钥”仍然适用于默认的直接控制模式；本 ADR 只对显式启用的自动任务模式开例外。

4. **两种控制语义保持一致。**
   自动任务与直接模式共用同一 `ActionService`、`ControlManager` 与 `ActionLedger`：
   单动作互斥、租约、幂等键、未知结果不重放、F9/接管优先，均不因新功能而改变。

5. **执行器只能做政策允许的事。**
   三层交集 = 注册工具 ∩ Mod 当前能力 ∩ Web 政策 ∩ 任务收紧；
   控制会话、任务派单、配置/密钥、存档、联机、文件与 shell 永不暴露给执行模型。

6. **单人优先。**
   D1 执行器只运行单人任务；联机派单明确拒绝，原有联机直接控制保留。

## 后果

正面：

- 主模型不必逐步微操，减少宿主往返；
- 目标、预算、限制、证据都在 Bridge 内可审计；
- 不配置模型的用户完全不受影响。

代价与限制：

- 项目需要保管一份模型凭据（本地私密文件，非加密保险箱）；
- 执行模型可能比直接调用更慢或更贵，效率提升不做预先承诺；
- 只有四种机器可验证条件，跨日/睡觉/存档类目标仍需人工判断；
- 政策能力表有限，未实现的参数保护一律拒绝，不会“先放开再祈祷”。

## 被否决的替代方案

| 方案 | 否决原因 |
| --- | --- |
| 只做任务记忆与提示词，不做执行循环 | 不满足用户明确需求，属于“只连接 UI 的演示” |
| 在项目内下载/训练/启动模型权重 | 超出范围，体积与许可风险高 |
| 让执行模型直接调用 Mod 或自建第二条写连接 | 破坏单写者、幂等与账本事实 |
| 自动继承 DSH/Codex 的模型账号或 OAuth | 越权获取宿主密钥，且不可审计 |
| 用长串未逐步核验的宏冒充“效率优化” | 无法停止、无法核对、无法归因 |
| 默认开启并要求配置模型 | 把升级变成强制购买模型服务 |
