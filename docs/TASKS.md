# 实施任务与依赖

更新：2026-10-29，0.2.0-preview.1。以下 M0–M5 任务表保留原始规划勾选，不能据其空复选框判断代码尚未实现。当前单人核心、Linux 平台层、Docker 单人基础设施与 MP1 实验性实现已进入集成验证；发布、实际测试和仍未验收的游戏行为以 [RELEASE_VALIDATION_20261029.md](RELEASE_VALIDATION_20261029.md) 为准。稳定版仍需完成下文真实任务/长期游玩门槛，预览发行不代表这些门槛通过。

状态顺序：待开始 → 进行中 → 待验收 → 已验收；遇到外部阻塞写明具体原因和下一步。P0 是正确性及贯通前提，P1 是首版交付功能，P2 是后续扩展。

## 2. M0：基础

### BASE-01 — 来源、迁移清单与许可

- [ ] 列出旧 Mod、DSH 适配器中迁入、重写、保留历史、排除的文件，记录上游提交及本地差异摘要。
- [ ] 确认 0.3.0 包与工作区源码之间的差异；对作为基线的源文件记录哈希。
- [ ] 保留上游许可证和版权声明，建立 NOTICE 与依赖来源清单；项目作者信息依据真实仓库信息填写。
- [ ] 排除旧 `.git`、Jev 决策层、用户输出、存档、游戏 DLL 和凭据。
- 验收：依据清单可定位每项来源；新仓库不会依赖个人机器绝对路径；源码只进入一个明确的新项目根目录。

### BASE-02 — 协议与业务状态

- [ ] 将 [接口草案](PROTOCOL.md) 转成共享 Schema、类型、错误码、参考样例。
- [ ] 明确 28 个迁移工具的参数、读写分类、取消语义及后验字段。
- [ ] 完成会话、动作、暂停状态的边界与崩溃窗口测试设计。
- 验收：正常/非法参数样例能够机器校验；同 ID 不同参数、旧世界和未知效果均有确定处理规则。

### BASE-03 — 工程构建与 CI

- [ ] 固定 Node、包管理器、MCP SDK、数据库驱动及 Web 构建依赖；提交锁文件。
- [ ] 建立 TypeScript、Mod 本地构建、单元与契约测试命令；通过配置指定游戏安装位置。
- [ ] 公共 CI 运行无游戏依赖检查；受控实机环境单独说明，禁止上传游戏依赖。
- 验收：新目录检出后能构建核心和 Web 骨架；缺少游戏引用时报可操作诊断；构建不写入真实游戏目录。

## 3. M1：三个客户端只读贯通

### MOD-01 — 游戏侧连接

- [ ] 提取进程内观察、游戏阶段和实例标识，保持所有游戏对象访问在主线程。
- [ ] 握手校验内部协议、凭据、能力；增加连接和消息上限。
- [ ] 发布入口按白名单提供能力，审计旧 warp/skipevent/diag。
- 验收：标题页与已加载存档都能诊断；错误凭据、错误协议和网页直连被拒绝，不触发游戏动作。

### CORE-01 — 常驻服务

- [ ] 实现启动/停止、端口冲突诊断、单实例约束及服务发现。
- [ ] 提供 Mod 连接状态、只读重连及 SQLite 迁移框架。
- [ ] 分离凭据、日志、数据库和静态文件位置；不同客户端不创建重复控制器。
- 验收：游戏关闭时服务仍能诊断；启动第二个实例有明确结果；数据库不可写时禁止派发写动作。

### MCP-01 — 双传输

- [ ] 注册只读工具，使用结构化结果及文字摘要。
- [ ] HTTP 和 stdio 走相同业务实现；stdio 正常退出不带走共享服务。
- [ ] 测试工具发现、非法参数、认证、旧协议兼容及取消处理。
- 验收：两个传输得到等价状态；正常日志不污染 stdio；不支持的协议返回明确错误。

### OBS-01 — 观察可用性

- [ ] 完整保留日期时间、资源、菜单、出口、对象引用和阻塞原因。
- [ ] 引用绑定世界/地图/菜单；详情按需读取，限制大地图与箱子输出。
- [ ] 截图返回标准图片内容；文字能力保留独立可用性。
- 验收：模型能仅根据结构化信息选定一个真实附近目标；换图后旧引用被拒绝；输出不因压缩丢失导航信息。

### CLIENT-01 — 实际客户端接入

- [ ] DSH、Codex、Claude Code 分别记录实际版本和 MCP 配置方式。
- [ ] 每个客户端通过 HTTP、stdio 各完成工具发现和只读调用。
- [ ] 记录图片是否能显示、参数校验、工具权限和协议版本。
- 验收：同一游戏状态下各客户端读取一致；图片能力按模型/宿主组合单独标记，未测试组合不能填通过。

## 4. M2：控制与玩法

### CTRL-01 — 控制会话

- [ ] 实现显式 start/status/checkpoint/end、客户端归属、租约与 Mod 控制权代次。
- [ ] 原子获取控制；拒绝非持有者、已关闭会话与跨世界写入。
- [ ] 网页与 MCP 共用控制状态，多个聊天不能被当成一个隐式会话。
- 验收：并发 start 只有一个成功；旧请求迟到不夺回控制；只读访问不续租。

### CTRL-02 — 停止与断线看护

- [ ] stop 优先处理，释放移动、工具和实时输入。
- [ ] Mod 独立 watchdog 和游戏内接管热键；Bridge 异常退出仍能工作。
- [ ] 测量健康主线程条件下停止延迟，明确卡死场景的未知状态。
- 验收：超时、断连、取消与人工接管均不残留持续输入；旧待处理请求不能在接管后执行。

### CTRL-03 — 默认分步暂停

- [ ] 动作结束尝试正常暂停；区分自有暂停菜单、用户菜单和游戏内对话。
- [ ] 返回真实暂停状态；准备下一动作时仅关闭自己创建的菜单。
- [ ] 连续实时模式具有明确启用、截止时间和退出流程。
- 验收：普通场景暂停前后游戏时间保持一致；剧情无法暂停如实标记；关闭用户菜单的回归测试不得通过错误实现。

### ACT-01 — 基础操作

- [ ] 迁移 move/select/use/interact/menu/wait/pause/closemenu/stop。
- [ ] 动作前有界等待，正常距离、碰撞、工具和菜单条件校验。
- [ ] 迁移路径失败、地图出口、动画阻塞和引用失效的恢复信息。
- 验收：完成观察→走近→使用工具→核验→暂停；不可达目标停止并有原因；不以瞬移或改资源补成功。

### ACT-02 — 资源与经济

- [ ] 迁移 shop/buy/ship/container/recipes/craft/place/eat/equip。
- [ ] 统一动作意图、Mod 去重与最终收据；检查物品、货币和材料变化。
- [ ] 覆盖满包、数量不足、部分完成、重复 ID、返回丢失和正常取消。
- 验收：资源守恒或游戏规则对应的消耗可核对；出货入箱与次日结算分开；没有不明结果自动重做。

### ACT-03 — 实时动作

- [ ] 保留有作用域的逐帧输入，不替换整个输入系统。
- [ ] 钓鱼报告实际收获；战斗报告真实伤害、击败或停止原因。
- [ ] 时间与生命阈值可配置且受服务端上限约束。
- 验收：一次真实捕鱼与基础近战成功；中途取消立即进入收尾；超时不记为捕获或击杀。

### ACT-04 — 加载与跨日

- [ ] 标题页枚举精确存档标识，正常 load；不自动退出正在运行的存档。
- [ ] 处理过渡、结算菜单、保存和 ready 状态。
- [ ] 加载/切档使旧会话和引用失效，历史收据仍可读。
- 验收：正常睡觉并跨日保存；load 的 accepted 与真正 ready 分别有证据；旧会话不能操作新存档。

## 5. M3：Web 与配置

### WEB-01 — 状态页面

- [ ] 连接、版本、游戏概况、背包、地图和按需截图页面。
- [ ] 事件序号与断线提示，断流后重新取完整状态。
- [ ] 中文提示、键盘可用性、常用桌面宽度；控制按钮在只读状态下明确不可操作。
- 验收：真实浏览器显示与工具快照一致；页面失去连接不继续伪装成实时状态；无阻断交互的错误。

### WEB-02 — 人工接管与日志

- [ ] 显示当前控制者和在途动作，提供停止、接管及暂停结果。
- [ ] 动作时间线明确区分受理、执行、成功、部分完成和未知。
- [ ] 导出可预览的脱敏问题包，Agent 说明与事实收据分别标记。
- 验收：实机接管后旧控制者不能继续移动；问题包含复现信息且不含凭据与个人完整路径。

### CLIENT-02 — 配置生成

- [ ] 从实际安装路径、端口和客户端能力生成各自配置格式。
- [ ] 提供 HTTP 与 stdio，注明环境变量/凭据配置与连接诊断。
- [ ] 写入配置仅在用户显式选择安装后进行；支持预览和备份回退。
- 验收：中文及含空格路径可用；不覆盖其他 MCP 服务器；缺少客户端或权限时错误明确。

## 6. M4–M5：发布与稳定性

### QA-01 — 契约与故障

- [ ] 执行验收文档中的协议、控制、取消、资源和崩溃窗口矩阵。
- [ ] 保存可重现的模拟场景与真实游戏证据，区分两者。
- 验收：所有首版强制正确性检查通过；未解决的重复消费或控制失效阻断发布。

### QA-02 — 三客户端短任务

- [ ] 在相同准备条件下，三个宿主分别完成同一项短游戏任务。
- [ ] 每个宿主至少一种传输完成写动作；另一种传输完成等价动作及停止抽检。
- 验收：实际工具调用与游戏变化能对应；宿主只显示“已连接”不算完成；模型与客户端版本有记录。

### REL-01 — Windows 安装包

- [ ] 打包 Mod、常驻服务、Web、适配器和经过许可核对的运行时。
- [ ] 安装前检测游戏/SMAPI/端口/旧 Mod；升级保存原配置并提供回退。
- [ ] 包含来源、版本、哈希及文件清单；排除游戏 DLL、存档和本机凭据。
- 验收：新的安装目录可启动；构建包与实际安装版本一致；回退不丢失用户配置。

### REL-02 — 发布说明

- [ ] 中英文快速开始、三个宿主连接示例、支持矩阵、故障诊断、卸载回退。
- [ ] 记录已验收玩法与已知限制，说明模型与预算由宿主提供。
- 验收：新用户无需了解内部开发路径即可完成只读调用和短游玩任务；文档中的版本与包一致。

### QA-03 — 持续游玩

- [ ] 至少一个客户端完成连续七个游戏日，包含种植、照料、收获、出货及收入核对。
- [ ] 固定目标、固定初始条件、独立副本进行五轮任务，至少四轮无人工补救完成。
- 验收：区分模型决策失败和工具缺陷；技术正确性检查全部通过，游戏收益有真实证据；跨季节未测则明确列为未测。

### QA-04 — 安装与存档完整性

- [ ] 执行新目录安装、中文/空格路径、旧版冲突、端口占用、卸载回退。
- [ ] 核对非测试存档的清单和哈希；夹具只位于明确的独立测试存档。
- 验收：发布包按文档可复现；原存档未被测试改动；没有将初始夹具资源计为 Agent 收益。
