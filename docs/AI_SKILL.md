# 给 AI 使用的游玩 Skill

项目提供 [stardew-player](../skills/stardew-player/SKILL.md)：把星露谷攻略、MCP 操作流程及两层游玩日志组合成一个可携带技能包，适用于 DSH、Codex、Claude Code 等 Agent。

这是主 Agent 的行为指引，不额外启动模型，也不把攻略自动注入 Bridge 的后台执行模型。任务助手是否开启仍由玩家决定。

## 使用方法

1. 先按 [CLIENTS.md](CLIENTS.md) 接好本项目 MCP，确认模型能看到实际 `stardew_*` 工具。
2. 将完整的 `skills/stardew-player/` 文件夹交给宿主的技能导入/技能目录机制，保留 `references/`、`assets/` 和 `agents/`。只有入口文件不够，攻略和日志规则在引用文件中。
3. 在宿主中选择这个技能，或明确要求读取入口文件。不支持技能机制的宿主也可直接读取入口，再按链接读取引用；不必修改项目源码或全局系统提示词。

可以直接交给 AI：

```text
读取项目 skills/stardew-player/SKILL.md，并按它游玩当前星露谷存档。
先核对世界/角色与短期、长期日志，处理未决动作，再推进一个可核验的小目标。
没有特别任务时，在保留资源和回家余量的前提下自由游玩。
每个小目标结束更新短期检查点，结束游玩或出现新经验时合并长期日志。
告诉我日志实际保存位置；没有持久存储时明确说明，不能声称已经保存。
```

Codex 支持技能调用时可使用 `$stardew-player`。DSH/Claude Code 的导入入口取决于宿主版本；本项目不假定一个统一安装按钮，不自动修改各宿主配置。Skill 被读取不表示 MCP 已连接或游戏已加载。

## 技能内容

| 文件 | 用途 |
| --- | --- |
| `SKILL.md` | 每轮决策、恢复、执行与收尾；要求维护两层日志 |
| `references/gameplay-guide.md` | 每日优先级、农事时间、四季路线、矿洞/钓鱼/动物、资源规划与事实来源 |
| `references/bridge-playbook.md` | 直接 MCP、可选执行模型、真实工具参数及记忆 API 的使用边界 |
| `references/journaling.md` | 日志作用域、写入频率、故障恢复、长期提炼、上下文压缩与效率复盘 |
| `assets/*-term.template.md` | 可复制的短期与长期空白模板 |
| `agents/openai.yaml` | 支持该格式的宿主可用的显示信息，其他宿主可忽略 |

## 日志保存与隐私

有文件能力时，在宿主已授权工作目录的 `playlogs/<world-key>/<agent-key>/` 保存日志；项目 Git 忽略 `playlogs/`，攻略文件本身保持通用。短期当前检查点与长期目标/经验分开，不让每步流水占满上下文。不能直接把游戏显示名拼成路径，也不能混用不同世界或 Agent 的未决动作。

仅 MCP 时，可使用实际可用的 `stardew_memory` 保存分片，限当前作用域和 owner；默认私有，不能保证其他客户端自动读到。记忆服务不可用则交付可复制的聊天检查点，明确未持久化；不为了记日志自动启用任务助手或索取模型 Key。

日志是行为规范：主 Agent 需要真实执行写入并核对结果；不新增游戏自动日志采集、跨客户端同步或效率提升的保证。Bridge 自身动作账本继续承担原始回执与不重放语义。

## 发行范围
